# NotchFlow 功能清单

## 文档目标

先把一个 macOS 刘海应用原型的功能范围列清楚，后面方便我们一起增删、排序、定版本。

## 产品方向候选

- 工具型：媒体控制、系统状态、快捷动作
- 工作流型：计时器、任务状态、开发会话入口
- 混合型：先有一层实用工具，再补少量工作流卡片

当前建议：

- 第一版先偏工具型，把刘海面板和正在播放体验做扎实，再决定要不要往工作流方向扩。

## 第一版必须有

### 应用外壳

- [ ] 菜单栏应用入口
- [ ] 后台常驻，不在 Dock 中显示
- [ ] 开机自启
- [ ] 设置窗口

### 刘海面板

- [ ] 顶部中央悬浮面板
- [ ] 在刘海屏 Mac 上正确贴合刘海定位
- [ ] 在非刘海屏上有降级布局
- [ ] 顺滑的展开和收起动画
- [ ] 多屏处理

### 触发方式

- [ ] 悬停展开
- [ ] 点击后固定展开
- [ ] 全局快捷键唤起或切换
- [ ] 无操作一段时间后自动收起

### 核心卡片

- [ ] 正在播放卡片
- [ ] 播放或暂停控制
- [ ] 上一首或下一首

### 基础质量

- [ ] 重启后恢复基本状态
- [ ] 在全屏应用和 Spaces 下行为正常
- [ ] CPU 和内存占用保持轻量

## 第一版可选

### 效率功能

- [ ] 快捷启动卡片，支持应用、文件夹、网址、脚本
- [ ] 计时器卡片
- [ ] 简单待办卡片
- [ ] 剪贴板历史预览
- [ ] 日历下一项事件卡片
- [ ] 提醒事项摘要

### 系统工具

- [ ] 电量卡片
- [ ] 音量和亮度卡片
- [ ] Wi-Fi 和网络摘要
- [ ] 天气摘要

### 交互扩展

- [ ] 文件拖放 shelf
- [ ] 临时文件暂存区
- [ ] 对拖入文件执行快捷打开或分享动作

### 视觉打磨

- [ ] 类似 Live Activity 的紧凑态和展开态
- [ ] 单卡片级别的动效
- [ ] 主题预设
- [ ] 自定义面板尺寸和圆角细节

## 后续探索

- [ ] 电池充电区间控制，支持“只充到某个百分比”
- [ ] 电源适配器开关控制
- [ ] AI 助手状态卡片
- [ ] 编程会话卡片，展示任务或审批状态
- [ ] Shortcuts 和 AppleScript 集成
- [ ] 终端会话钩子
- [ ] Zoom、Meet、Slack 一类的会议状态卡片
- [ ] 番茄钟或专注模式场景
- [ ] 第三方卡片插件系统
- [ ] 按上下文轮换的小组件

### 电池控制方向备注

- 参考项目：`mhaeuser/Battery-Toolkit`
- 目标能力：限制充电上限，例如只充到 `80%`
- 实现方式不是单纯读电量，而是监听电量变化并主动关闭或恢复充电
- 大概率需要特权后台 daemon、XPC 通信和 SMC 相关控制
- 当前判断只适合单独立项，不放入 NotchFlow 第一版
- 兼容性重点：Apple Silicon、重启后的恢复行为、系统优化充电冲突、休眠行为

## 权限和集成说明

### 不太需要特殊权限，或者实现相对直接

- 菜单栏应用
- 刘海悬浮面板
- 本地计时器
- 快捷启动器
- 基本 UI 状态和动画

### 往往需要系统权限或额外集成

- 全局快捷键
- 切换窗口或聚焦其他应用
- UI 自动化
- 读取其他应用更丰富的状态
- 自动控制外部应用

常见需要：

- Accessibility 权限
- Automation / Apple Events 授权
- 媒体接口或应用专属集成

## 早期版本暂不纳入

- [ ] 真正替换系统刘海
- [ ] 像 iPhone 那样深度接管系统级灵动岛行为
- [ ] 保证支持所有第三方应用的内部状态读取
- [ ] 在核心交互还没跑顺前就上复杂云同步

## 建议的首个开发顺序

1. 菜单栏外壳和刘海面板
2. 定位、悬停、点击、快捷键触发
3. 正在播放卡片
4. 设置页和开机自启
5. 多屏和全屏场景打磨
6. 评估是否加入快捷启动卡片
7. 评估是否加入计时器卡片

## 还要继续拍板的问题

- [ ] 第一版气质更偏工具，还是更偏工作流？
- [ ] 默认触发方式是悬停优先，还是快捷键优先？
- [ ] 文件拖放 shelf 是否足够核心，值得进第一版？
- [ ] 品牌表达是只强调刘海屏，还是对所有 Mac 都做优雅兼容？
